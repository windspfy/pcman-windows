# PTT／PTT2 名單與關鍵字顯示過濾

建議 Issue 標籤為 `ready-for-agent`。

## Problem Statement

閱讀看板時，使用者希望略過特定帳號的文章或推文，也希望能降低劇透等內容的可見度；反過來，也可能想讓關注的帳號或字詞更醒目。不同情境需要不同強度的處理，但仍需保留終端機的欄位位置、原文與操作線索。

## Solution

在 PTT 與 PTT2 的文章列表和閱讀畫面提供 ID 與關鍵字名單，可作為黑名單（星號、隱藏）或關注名單（標色）。兩站所有看板共用設定。每條規則以勾選決定套用於列表、內文、推文，並可使用共用預設效果或個別指定。初始預設為等寬星號。

## User Stories

1. 身為兩站的讀者，我希望在 PTT2 測好的規則能直接用在 PTT，以便只維護一份清單。
2. 身為讀者，我希望在同一份清單管理 ID 與關鍵字，並以類型區分，以便一眼看到所有規則，同時精準比對帳號與搜尋內文中的字詞。
3. 身為讀者，我希望 ID 忽略英文大小寫並比對完整帳號，以免誤中名稱相似的人。
4. 身為讀者，我希望直接輸入關鍵字就搜尋包含該詞的內容，以便快速建立常用規則。
5. 身為讀者，我希望關鍵字在內文中可選只遮關鍵字本身或整行，以便在可讀性與防劇透之間取捨。
6. 身為讀者，我希望每條規則都能勾選列表、內文、推文，以便只處理我選定的位置。
7. 身為讀者，我希望未指定效果的規則使用共用預設，以便一次調整多條規則。
8. 身為讀者，我希望個別規則可指定固定效果，以便保留例外。
9. 身為讀者，我希望列表中命中的文章除了編號以外都被處理，同時看得到游標位置，以便知道這一列仍存在並繼續瀏覽。
10. 身為讀者，我希望開啟命中作者的文章時處理作者、標題與正文，以便仍可閱讀其他人的推文。
11. 身為讀者，我希望推文者 ID 或推文關鍵字命中時處理推文者與發言，並保留推噓符號與時間，以便略過或標出該則推文，同時知道那裡有一則推文。
12. 身為讀者，我希望能用標色同時改字色和底色，以便關注特定內容，或把字色設成接近底色達到淡化效果。
13. 身為讀者，我希望跨越可確認自動折行的關鍵字也能命中，以免劇透因排版而漏出。
14. 身為讀者，我希望星號與隱藏都保留原來的文字位置，以便照常用游標瀏覽。
15. 身為讀者，我希望多條規則重疊時較強的效果優先，以免標色意外顯露要隱藏的文字。
16. 身為讀者，我希望複製可取得完整原文，以便保留或轉用原始內容。

## Implementation Decisions

* 建立連線時依網址的主機名稱辨識 PTT2，結果沿用至該連線結束。登入後繼續辨識畫面與目標欄位，僅在可辨識的文章列表或閱讀畫面套用過濾。無法辨識畫面或欄位時，該處照常顯示原文。
* 套用位置：
  * **列表**：比對作者與標題（不含分類）。命中時保留最左側的游標標記（`●`、`>`）與文章編號（含置底的 `★`），其餘推文數、日期、作者與標題都處理，避免整列消失被誤認為程式錯誤。
  * **內文**：比對文章檔頭作者、標題與正文。作者命中時處理檔頭作者、標題與整篇正文。關鍵字命中時依「內文遮罩」只處理關鍵字本身，或處理命中的整個畫面列。
  * **推文**：比對推文者與發言（不含推噓符號與時間）。命中時處理推文者與發言，保留開頭的推／噓／→ 符號與行尾的日期時間。
* 文章列表依 PTT 實際格式辨識：推文數欄與日期相連（例如 `+爆11/24`），標題標記為 `R:` 或一個全形符號（□、轉、鎖等）。
* 閱讀畫面中，從看板列表進入的文章即使未看到檔頭（例如直接跳至最後一頁），仍套用推文與正文規則；作者規則僅在曾看到檔頭時套用。第一頁沒有看板檔頭（如站內信）時不套用。底列空白的重繪中畫面不重設狀態。
* 關鍵字一律為「包含」比對，忽略英文大小寫與用來對齊的填補空白，保留字詞間的空格與標點。
* 不提供「整段」「整篇」等更大的內文遮罩範圍：PCMan 只看得到目前畫面，段落或文章跨頁時只能遮到部分內容，容易被誤認為程式錯誤。
* 正文一般逐畫面列比對。可確認為同一段自動折行的列接續比對；關鍵字跨列時，兩列各自處理所涉及的部分（只遮關鍵字）或整列（單行）。遇到手動換行或來源不明時分列比對。使用者功能說明須保留此判定方式與可能漏判的例子。
* 同一位置命中多條規則時，以隱藏、星號、標色的優先順序合併結果，順序不受規則建立時間影響。
* 隱藏使用每格當前底色作為字色。星號按終端欄寬替換，雙欄中文字顯示兩個星號。標色共用一組前景色和底色，各自可選保留原色或終端機色盤中的顏色。
* 遮蔽只影響顯示。保留終端原文與列、欄位置，複製隱藏或星號遮蔽的選取範圍仍得到原文。
* 設定檔 `PttFilter.dat` 在正式發布前不保留舊格式相容性；版本不符時以空清單開始。

## Testing Decisions

* 在同一條以主機名稱辨識的 PTT2 連線上，登入後從文章切換到編輯器，再返回文章。三個畫面都顯示相同關鍵字，確認只在文章中套用遮蔽。另回放無法辨識的畫面，確認即使出現該關鍵字也會保留原文。
* 以實際 PCMan 視窗為主要驗收層級，沿用本機連線回放與剪貼簿測試做法。經設定介面建立規則，重播固定畫面，觀察文字、色彩、欄位位置及複製結果。測試應允許內部資料結構調整。
* 驗證 PTT 與 PTT2 共用規則、跨板生效，並切換到編輯器、站內信及其他 BBS，確認原文正常顯示。
* 用完整 ID、大小寫變體及相似 ID 驗證帳號比對。用標點、字詞間空格及對齊填補驗證關鍵字。分別只勾選列表、內文、推文驗證套用位置。
* 改動共用預設，確認使用預設的規則更新，個別指定的規則仍照指定效果顯示。以同一則推文同時命中 ID 與關鍵字，驗證推文者與發言採較強效果，推噓符號和時間仍可讀。
* 用具有不同底色的中英文混排畫面，驗證隱藏、等寬星號與局部換色。選取同一段文字複製並比對原文。
* 將「暴」與「雷」分置相鄰兩列。可確認的自動折行應命中「暴雷」，依內文遮罩處理兩列的關鍵字部分或整列。手動換行及原因不明時應分列比對。捲動與重繪後重驗。

## Out of Scope

其他 BBS，以及 PTT／PTT2 的站內信、聊天室和編輯畫面。此版不包含每板獨立清單、萬用字元、正規表示式、整段或整篇遮罩、任意 RGB 配色、移除終端列或過濾剪貼簿原文。

## Further Notes

PCMan 已可辨識遠端自動折行模式並處理右邊界。實作時需驗證畫面捲動、重繪與伺服器重新送出內容後，能取得哪些列的折行來源。不得僅依上一列填滿右邊界推定為自動折行。
